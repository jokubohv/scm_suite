# FS-13 — Consigned Inventory Management

> **Scope.** Backend only. No UI/mobile/analytics/integration build scope. SCM Mobile permanently excluded.

> **Implementation spec.** Authority: `design/FEATURE-SETS.md` §7.14 + `design/feature-sets.json` and
> `design/DATA-MODEL.md` §15. Vendor-consigned inventory is documented NetSuite core inventory behavior: stock is
> physically received/stocked/transferred but paid for only when consumed/sold, with ownership as a posting dimension.
> The documented incompatibilities (no assembly/manufacturing; no worksheets; no consigned↔owned status flip) are
> enforced as tenant guards (D6). Extensions beyond DATA-MODEL are marked `EXT`/`ASSUMPTION` and reported in §14.

## 1. Objective and source coverage

Deliver vendor consignment as a first-class ownership dimension: agreements covering item/location pairs, consigned
receipts (T-21, no AP liability), ownership-transfer-on-consumption/sale (T-22, creating the vendor bill only when the
stock is consumed), consigned adjustments/counts (T-23, no AP effect), consigned movements that preserve ownership,
consumption audit data for reporting/finance, and the documented consigned×assembly incompatibility guard. Consigned
positions are ledger positions with `ownership=CONSIGNED`; FS-13 owns the agreements/documents and drives all postings
through `inventory.ledger`/`costing.engine` contracts (never writes ledger rows itself).

## 2. Scope

**In scope (backend):**
- Consignment agreements + covered item/location configuration (consigned/owned statuses, consigned unit cost,
  min/max quantities, payment trigger ON_CONSUMPTION/ON_SALE), lifecycle and approvals.
- Consigned receipt into `ownership=CONSIGNED` positions (T-21) with lot/serial/bin detail; no vendor bill/AP liability.
- Ownership transfer on consumption/sale (T-22): CONSIGNED→OWNED for the consumed qty, vendor bill creation through the
  FS-08 contract, consumption audit row, consigned finance intents.
- Return-to-vendor and ADJUST ownership-transfer documents (T-23/DATA-MODEL enum), for consigned adjustments/counts
  and returns; no AP effect.
- Consigned movements (bin/location transfers) preserving ownership via the ledger transfer contracts (T-29/T-09).
- Consumption reporting data (`consignment_consumption`) for FS-15 `v_consigned_balance` and consumption reports.
- Consigned-balance read surface (owned vs consigned quantities/values kept separate).
- D6 guards: consigned×assembly/manufacturing mutual exclusion; worksheets/ordinary adjustments prohibited for
  consigned items; consigned↔owned status changes prohibited (only T-22 changes ownership).

**Out of scope / deferred:**
- Consignment reporting workbooks/dashboards (FS-15 read model only), consignment consumption report rendering.
- Integration/automation of purchasing partner drops (SuiteProcurement, EDI), vendor portals and bill capture.
- Consigned inventory in WMS/Manufacturing flows: WMS owns owned-stock inbound/outbound (FS-11 §14 C-7); manufacturing
  is mutually exclusive by guard. No WMS/mobile consigned screens.
- GL/AP/payment execution: only journal intents + vendor-bill creation via FS-08 (no payments).
- UI enabling/disabling screens: feature flags via platform admin; guard API returns eligibility errors.

Business rules and invariants:

- `DM-CONS-01`: consigned positions are created only by T-21 through an ACTIVE agreement; owned and consigned balances
  never merge — the same posting key with different `ownership` is a different position (`INV-27`).
- `DM-CONS-02`: T-22 creates the vendor payable/bill at consumption/sale (pay only when sold) through the FS-08
  contract and writes exactly one `consignment_consumption` row per transferred line (`uq(source_transfer_line_id)`).
- `DM-CONS-03`: status changes between consigned and non-consigned are prohibited; only T-22 changes ownership;
  T-30 status changes must never mix `is_consigned` true/false.
- `DM-CONS-04`: inventory worksheets are prohibited for consigned items; adjustments/counts use T-23 (consigned
  transfer type ADJUST), rejecting ordinary adjustment/worksheet paths.
- `DM-CONS-05`: assembly/manufacturing features and consigned inventory are mutually exclusive per tenant (flag guard,
  enforced at tenant enable + agreement item validation; see §14 C-4 for the bidirectional limitation).
- `DM-CONS-06`: consigned items support lot/serial and bins; bin-level consigned qty is distinguished by the consigned
  status/ownership column; transfers preserve both.
- `DM-CONS-07`: TERMINATED/SUSPENDED agreements block new receipts/transfers but never block consumption of existing
  consigned stock; reactivation requires re-approval.
- `CONS-RULE-01` (valuation): consigned value is tracked with `value_inbound(CONSIGNED)` and ownership-transfer value
  `value_ownership_transfer` in FS-05; journal intents CONSRCPT/CONSOWN/CONSADJ are asserted via the finance read API;
  no GL/AP is written by FS-13.
- `CONS-RULE-02` (bill timing): vendor bill creation must occur exactly in the same transaction as T-22 posting
  (`vendor_bill_id` set on the posted transfer); if FS-08 is unavailable the whole transaction fails (no ownership
  transfer without payable).
- `CONS-RULE-03` (quantity guards): receipt/consume/return/adjust quantities are positive base-UoM decimals; serial
  counts must equal qty; lot quantities cannot exceed lot on-hand per FS-06; consigned qty cannot go negative.
- `CONS-RULE-04` (implicit ownership defaults): any posting to a consigned position must carry
  `ownership=CONSIGNED`; omitting ownership defaults to OWNED and cannot touch consigned balances (409
  `CONSIGNED_POSITION_REQUIRES_OWNERSHIP`).
- `CONS-RULE-05` (guard audit): every rejected guard attempt is audited (`consigned.guard.rejected`) with reason and
  configuration snapshot.
- Cross-set invariants: `INV-01`/`INV-02` (qty/value conservation on every T-21/22/23 pair), `INV-09` append-only
  ledger, `INV-25` tenant isolation, `INV-26` state machines, `DM-GLOBAL-01..10`, `DM-CONS-01..07`.

State machines:

- `consignment_agreement`: `DRAFT → ACTIVE` [approval + valid dates + guard]; `ACTIVE ↔ SUSPENDED`;
  `ACTIVE|SUSPENDED → TERMINATED` [zero consigned stock or disposition plan]; no un-terminate.
- `consignment_ownership_transfer`: `DRAFT → PENDING_APPROVAL → APPROVED → POSTED`; `POSTED → REVERSED`; unposted →
  `VOID`; `CONSUME` requires linked external sale ref or approved manual consumption (DATA-MODEL §19). Posting
  transitions call FS-04 with the document id as `source_doc_id` and store `posted_transaction_id` (unique).
- Side effects: every transition writes `audit_event` + one outbox event per aggregate change; POSTED writes the
  consumption row (T-22 only) + vendor bill ref (T-22 only) in the same transaction.

### 5.6 Assembly/manufacturing guard detail (D6)

  readable; consumption (T-22) should be allowed to drain stock via a documented break-glass path before disabling.

  delete.
